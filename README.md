# xmrig-fleet

Консольное управление майнингом xmrig на всех ПК пула через tailnet.

Две части:

- **агент** (`XmrigFleet.Agent`) — маленький HTTP-сервис на каждой майнящей машине. Запускает и
  останавливает xmrig, читает его хэшрейт, снимает датчики железа, ставит и обновляет майнер.
- **консоль** (`XmrigFleet.Console`) — TUI на Spectre.Console на вашей машине. Опрашивает все ноды,
  показывает живую таблицу, считает электричество и доход, тянет баланс с Hashvault.

Связь — обычный HTTP поверх Tailscale. Порт агента закрыт файрволом на всё, кроме диапазона
tailnet (`100.64.0.0/10`), и дополнительно защищён общим токеном в заголовке `X-Fleet-Token`.

## Что умеет

| Пункт | Где |
|---|---|
| Старт / стоп / рестарт майнинга (на всех или выбранных нодах) | Miner control |
| Хэшрейт, шары, аптайм, пинг до пула | Dashboard |
| Добавление новых ПК списком из tailnet | Nodes → Discover from tailnet |
| Установка и обновление xmrig по указанному пути | Miner control → Install / update |
| Характеристики ПК: CPU, GPU, RAM, материнка | Hardware & sensors |
| Температуры, обороты, нагрузка | Hardware & sensors |
| Потребление электричества | Dashboard, Economics |
| Стоимость майнинга и планируемый доход | Economics |
| Состояние hashvault и баланс кошелька | Pool & wallet |
| Автоматическое ограничение мощности, когда за ПК работают | Miner control → Power limit |
| Майнинг на видеокарте, с паузой когда карта нужна человеку | Dashboard, `xmrig-fleet gpu` |

### Как ходить по меню

Стрелки **по кругу**: вниз с последнего пункта возвращает на первый, вверх с первого — на
последний. **Escape** — назад, то же самое, что пункт `< back`; в главном меню — выход.

Escape работает **в меню, но не в полях ввода**. Там, где консоль спрашивает текст или число —
адрес ноды, путь, цена киловатт-часа, — Escape не нажимается: в Spectre у текстового поля просто
нет такого понятия, и делать вид, что есть, было бы хуже, чем сказать прямо. Из «Add manually»,
где пять вопросов подряд, выход один — ответить до конца и не подтверждать запись, либо Ctrl+C.

Меню, где выбор что-то **разошлёт по нодам** — автозапуск, монитор сеанса, ограничение мощности —
имеют отдельный пункт `< back`, и Escape попадает именно в него. Это не украшение: раньше у них
было всего два ответа, и любой промах означал бы «выключить» на всех выбранных нодах.

## Установка консоли

Одной строкой, права администратора не нужны:

```powershell
irm https://raw.githubusercontent.com/XYphrodite/xmrig-fleet/master/deploy/install.ps1 | iex
```

Скачает последний релиз, распакует в `%LOCALAPPDATA%\Programs\xmrig-fleet` и пропишет PATH.
Дальше консоль обновляет себя сама:

```powershell
xmrig-fleet update          # поставить свежий релиз
xmrig-fleet update --check  # только проверить; код возврата 1, если есть новее
```

## Установка агентов на ноды

На каждой майнящей машине, из PowerShell **от администратора**:

```powershell
$env:XMRIG_FLEET_TOKEN = 'ваш-общий-секрет'
irm https://raw.githubusercontent.com/XYphrodite/xmrig-fleet/master/deploy/install-agent.ps1 | iex
```

Скрипт сам скачает агента из последнего релиза, поставит службу с автозапуском и
перезапуском при сбое, откроет порт **только** для диапазона tailnet и проверит, что API
отвечает.

Именно `irm ... | iex`, а не скачивание файла: запуск скачанного `.ps1` блокируется
политикой выполнения, а конвейер под неё не подпадает.

Если нужно поставить из своей сборки, а не из релиза:

```powershell
.\deploy\publish.ps1
.\deploy\install-agent.ps1 -Token "ваш-общий-секрет" -SourcePath .\publish\agent
```

В консоли: **Settings** → задать тот же токен, адрес кошелька, пул и цену киловатт-часа.
Затем **Nodes → Discover from tailnet** — машины подтянутся из `tailscale status`. Если MagicDNS
включён в tailnet и имена разрешаются на машине оператора, ноды добавляются по имени
(`rig-1.вашtailnet.ts.net`), иначе по адресу `100.x`; экран говорит, что именно записал.
Затем **Miner control → Push pool settings** и **Start mining**.

## Конфигурация

Консоль хранит `fleet.json` рядом с бинарником (путь можно переопределить переменной
`XMRIG_FLEET_CONFIG`):

```json
{
  "token": "общий-секрет",
  "agentPort": 47800,
  "pollIntervalSeconds": 5,
  "electricity": { "pricePerKwh": 5.0, "currency": "RUB" },
  "pool": {
    "apiBase": "https://api.hashvault.pro/v3/monero",
    "url": "pool.hashvault.pro:443",
    "wallet": "4..."
  },
  "nodes": [
    { "name": "rig-1", "host": "100.100.10.11", "port": 47800, "enabled": true,
      "powerFallbackWatts": 220 },
    { "name": "rig-2", "host": "100.100.10.12", "port": 47800, "enabled": true,
      "powerFallbackWatts": 310, "pricePerKwh": 7.2 }
  ]
}
```

`host` — адрес `100.x` или имя MagicDNS; консоль подставляет его в URL как есть. Имя переживает
смену адреса ноды, но требует, чтобы резолвер Tailscale работал на машине оператора: при
`--accept-dns=false` или чужом DNS нода станет недоступна по имени, хотя по адресу отвечала бы.

`electricity.pricePerKwh` — тариф по умолчанию. Если риг стоит в другой квартире, регионе или
тарифной зоне, задайте `pricePerKwh` прямо у ноды (**Nodes → Edit node**) — он перебьёт общий.
Стоимость считается по каждой ноде своей ставкой и потом складывается, поэтому средняя цена
никого не искажает. Валюта остаётся общей на весь флот: складывать рубли с долларами без курса
бессмысленно.

Агент хранит `appsettings.json` (токен, порт) и `miner.json` (путь к xmrig, пул, кошелёк) рядом
с собой. `miner.json` пишет консоль через **Push pool settings**, руками его трогать не нужно.

## Неинтерактивный режим

Те же операции доступны командами — удобно для планировщика:

```
xmrig-fleet status              # таблица состояния, код возврата 1 если нода недоступна
xmrig-fleet start [нода ...]
xmrig-fleet stop  [нода ...]
xmrig-fleet restart
xmrig-fleet economics
xmrig-fleet pool
xmrig-fleet update              # код возврата 2 при ошибке обновления
xmrig-fleet throttle            # на какой ступени мощности каждая нода и почему
xmrig-fleet autostart           # что нода делает при загрузке; --on / --off меняют
xmrig-fleet gpu                 # что майнит каждая видеокарта; --sync / --start / --stop
xmrig-fleet version
```

## Автозапуск майнинга при загрузке ноды

Нода, которая перезагрузилась сама — после отключения света, синего экрана или перезапуска
службы — по умолчанию возвращается **простаивать**: майнер ждёт команды, а команду дать
некому. Включается это в **Miner control → Start mining when the node boots** или командой:

```
xmrig-fleet autostart               # что настроено сейчас на каждой ноде
xmrig-fleet autostart --on          # майнить сразу после старта агента
xmrig-fleet autostart --off rig-2   # только этой ноде — ждать команды
```

Настройка хранится на самой ноде и переживает обновление агента. Что важно знать:

- **Включение не запускает майнинг прямо сейчас** — оно только про следующую загрузку.
- **Ограничение мощности главнее.** Ноду, которую ограничение остановило на нулевой ступени,
  автозапуск не поднимает: за этой машиной сидит человек.
- Нода, которой ничего не говорили, показывает `unset` и живёт по своему `appsettings.json` —
  это не то же самое, что выключённый автозапуск.
- Если нода отвечает `this agent is too old to autostart`, обновите агент:
  `xmrig-fleet upgrade-agents`.

## Ограничение мощности, когда за ПК работают

Нода не должна тормозить, пока за ней сидит человек. Агент раз в секунду смотрит, сколько
процессора занято **всем, кроме майнера**, и держит майнер на одной из пяти ступеней:

| Чужая загрузка ЦП | Майнер |
|---|---|
| до 10% | 100% |
| 10–25% | 75% |
| 25–45% | 50% |
| 45–70% | 25% |
| выше 70% | 0% — майнер останавливается |

Ступень — это доля от **полной скорости самого майнера**, а не от машины. Разница не
теоретическая: майнер в 6 потоков на 12-поточной машине занимает её примерно наполовину, и
лимит «50% машины» он бы просто никогда не достиг. Агент спрашивает у майнера число потоков и
пересчитывает: 50% от полной скорости на такой ноде — это 25% машины.

Ступени 25–100% — это ограничение процессорного времени через объект задания Windows.
Применяется мгновенно, майнер не перезапускается, huge pages и датасет RandomX остаются на
месте. Ступень 0 — настоящая остановка: майнер под ограничением всё равно держит около 2,3 ГБ
под датасет, а на машине с 16 ГБ именно эта память и делает работу некомфортной.

**Вниз — сразу, вверх — через две минуты тишины.** Помешать человеку дороже, чем потерять две
минуты майнинга; заодно короткий всплеск активности не раскачивает майнер вверх-вниз.

Пороги живут в `fleet.json`: общий блок `throttle` на всю ферму, у ноды — только отличия.

```json
"throttle": { "enabled": false, "floorLevel": 0, "rampUpSeconds": 120 },
"nodes": [
  { "name": "rig-2", "throttle": { "enabled": true, "floorLevel": 25 } }
]
```

`floorLevel` — ниже какой ступени не опускаться. Поставьте 25, если майнер на этой ноде лучше не
останавливать: перезапуск может не получить huge pages, а это на RandomX дороже всего.

```
xmrig-fleet throttle                    # где каждая нода и почему
xmrig-fleet throttle --sync             # разослать правила из fleet.json
xmrig-fleet throttle rig-2 --set=50     # прибить 50% руками, автоматика отключается
xmrig-fleet throttle rig-2 --auto       # вернуть управление автоматике
xmrig-fleet throttle rig-2 --log        # что нода решала и по каким показаниям
```

### Сколько стоит ступень

Ступень — это доля **процессорного времени**, а не доля хэшрейта. Хэшрейт падает сильнее.
Замерено на i5, 6 потоков, huge pages целы, майнер не перезапускался:

| Ступень | H/s | от полной скорости |
|---|---|---|
| 100 (лимита нет) | 2 210 | 100% |
| 50 | 610 | 27,6% |
| 25 | 325 | 14,7% |

Между 50 и 25 — ровно вдвое, то есть линейно. А вот **само включение лимита стоит около 45%
сверх пропорциональной потери**. Скорее всего дело в кэше: жёсткий лимит замораживает потоки,
у RandomX на поток 2 МБ рабочей области, шесть потоков на 12 МБ L3 — это весь кэш целиком, и за
время заморозки его вытесняет чужая работа.

Из этого следует практический вывод: **промежуточные ступени дорогие**. Ступень 75 отдаёт
примерно 41% хэшрейта взамен четверти освобождённого процессорного времени — плохой обмен.
Если нужен именно комфорт, а не тонкая регулировка, лестница из двух ступеней (100 и 0) честнее.

Пороги в таблице выше — предположение, а не измерение. Нода пишет каждое переключение вместе с
показаниями в `throttle.log` рядом с собой, и через неделю по нему будет видно, какая ступень
срабатывала зря. Правьте по журналу, а не по ощущениям.

### Журнал нагрузки

В тот же `throttle.log` нода пишет **одну строку в минуту о том, чем была занята**, независимо от
того, включён троттлинг или нет:

```
2026-09-05 16:10     load  off  other avg=3.1% peak=9.4% (1.1 of 12 threads)  miner=48.2%  mem=61%
2026-09-05 16:11     load  off  other avg=27.8% peak=94.1% (11.3 of 12 threads)  miner=44.9%  mem=78%
2026-09-05 16:12      50 -> 25  cpu=91.2% other=66.0% (7.9 of 12 threads) miner=25.2% mem=79%  ...
```

Читается тем же `xmrig-fleet throttle --log`.

**Зачем и среднее, и пик.** Загрузка, которая жала восемь секунд и отпустила на пятьдесят две, в
среднем выглядит скромно — а это ровно та картина, из-за которой человек тянется выключить
майнинг. Пик её показывает, среднее прячет.

`off` в колонке ступени и `0%` — **разные вещи**: первое значит, что за машиной никто не следит,
второе — что троттлинг остановил майнер намеренно.

Минута, которую не удалось измерить, пишется словами, а не строкой нулей: нули читались бы как
«машина отдыхала», то есть ровно наоборот. Разрыв во времени означает, что агент в этот момент не
работал — частичные минуты при остановке не дописываются, потому что строка за двадцать секунд
выглядит как строка за шестьдесят и занижала бы пик.

Файл ограничен 4 МБ плюс одна ротация — это примерно месяц истории и месяц до него.

Чего агент **не** видит: он служба в сеансе 0, поэтому ни движения мыши, ни активное окно ему
недоступны. Пока признак один — загрузка процессора, то есть реакция наступает после того, как
машина уже начала подтормаживать.

## Майнинг на видеокарте

Видеокарта майнит другую монету, другим майнером и на другом пуле, чем процессор. Поэтому у
неё отдельный майнер (**lolMiner**), отдельные настройки и отдельная пара колонок в таблице —
процессорный майнинг она не трогает вообще.

Включается в `fleet.json`: общий блок `gpuMiner` на всю ферму, у ноды — только отличия.

```json
"gpuMiner": {
  "enabled": false,
  "pauseWhile": { "tcpPort": 11434, "quietSeconds": 300 }
},
"nodes": [
  { "name": "rig-2",
    "gpuMinerPath": "C:\mining\lolMiner",
    "gpuMiner": {
      "enabled": true,
      "algorithm": "CR29",
      "poolUrl": "pool.example.com:4444",
      "user": "адрес.воркер"
    }
  }
]
```

`enabled` отвечает и на вопрос «что после перезагрузки»: карта, которой велено работать, вернётся
к работе сама. Отдельной настройки автозапуска у неё нет — в отличие от процессорного майнера,
который оператор останавливает и запускает по ходу дела, у карты это одно и то же решение.

**Алгоритм почти всегда принадлежит ноде, а не ферме.** RTX 4060 майнит Cuckaroo29, а
RX 6500 XT с 4 ГБ его просто не потянет — карта отвечает `Unsupported device`. Общая настройка
на всю ферму здесь редко бывает правильной, в отличие от пула и логина.

`user` пишется целиком, как его хочет конкретный пул: `XMR:адрес.воркер` у unMineable,
`адрес/воркер` у Kryptex. Одинакового формата у пулов нет, поэтому консоль ничего не
достраивает.

```
xmrig-fleet gpu                 # что майнит каждая карта, сколько шар и на каком пуле
xmrig-fleet gpu --sync          # разослать настройки из fleet.json
xmrig-fleet gpu rig-2 --start   # запустить карту
xmrig-fleet gpu rig-2 --stop    # остановить (процессорный майнер продолжит работать)
```

### Карта отдаётся человеку, когда она ему нужна

`pauseWhile` описывает, когда майнинг на карте отходит в сторону. Условие — **порт или
процесс**, а не приложение: локальная модель, игра и рендер хотят карту по одной и той же
причине, и разбирать их по именам смысла нет.

```json
"pauseWhile": { "tcpPort": 11434, "quietSeconds": 300 }
```

- `tcpPort` — пока к этому порту на ноде есть хоть одно живое соединение, майнер стоит.
  11434 — это Ollama.
- `processName` — то же самое, но по имени процесса, без расширения.
- `quietSeconds` — сколько тишины ждать перед возвратом. Отход — мгновенный.

Пять минут по умолчанию выбраны не случайно: модель между запросами остаётся в памяти карты, и
майнер, вернувшийся через десять секунд, выбьет её оттуда — следующий запрос будет ждать
загрузки вместо ответа. Замерено на RTX 4060: 53 tok/s со свободной картой против 19–24 tok/s,
пока она майнит.

Агент возвращает только тот майнер, который сам же и остановил. Если карту остановили руками,
она так и останется стоять — иначе пауза оспаривала бы решение оператора.

### Что важно знать

- **Ставить lolMiner пока нужно руками**, а путь прописывать в `gpuMinerPath`. Установки из
  консоли, как у xmrig, ещё нет.
- **Шары со звёздочкой стоят отдельной колонки.** Доля протухших шар — единственное, чем
  проявляет себя неправильно выставленный приоритет процесса: 18% брака и ни одного другого
  симптома. Колонка `GPU sh` показывает `принято/протухло`.
- **Хэшрейты карт не складываются.** 4,5 g/s Cuckaroo29 и 62 Mh/s NexaPoW — разные величины,
  и сумма у них бессмысленная. Поэтому в итогах их нет.
- На некоторых машинах майнер не работает из сеанса 0 — там нужен
  `"runInInteractiveSession": true`, и агент пока честно отвечает отказом вместо того, чтобы
  сделать вид, что запустил.
- Если нода отвечает `this agent is too old to mine on the GPU`, обновите агент:
  `xmrig-fleet upgrade-agents`.

### Сколько заработала карта

**Economics** показывает это отдельной таблицей — «Graphics cards, from payments the pool actually
made». В отличие от всего остального на этом экране, это **не прогноз**: это суммы, которые пул уже
отправил.

```
╭─Graphics cards, from payments the pool actually made──────────────────────────────────╮
│ Node         Coin      Per day   Value/day   Paid out   On the pool   Measured over    │
│ mks68i7rtx   XTM-C29     1 039     71.77 ₽   1 155.12   263.68 / 200  22 h, 5 payouts  │
╰───────────────────────────────────────────────────────────────────────────────────────╯
```

**Скорость считается по выплатам, а не по счётчику пула.** У Kryptex есть поле `reward.week`, и
оно выглядит подходящим, но на карте, которая майнит второй день, там лежит весь заработок целиком
— поделив на семь, получаешь заниженное втрое. На живой ферме это 178 XTM/сутки против настоящих
1 039.

**Окно всегда подписано.** «22 h, 5 payouts» — это то, за что посчитано. Две выплаты с разницей в
четыре часа не описывают сутки, и скорость без указания окна читается как суточная, хотя ею не
является. Если выплат меньше двух, вместо числа стоит «too few payouts to say»: одна выплата
говорит сколько, но никогда — как быстро.

**Настройки берутся с ноды, а не из `fleet.json`.** Адрес и пул живут там, где они правда — в
`miner.json` на самой машине. Карта, настроенная пушем прямо в агента, не оставляет в
операторском конфиге ничего, что можно было бы прочитать.

**Понимается только Kryptex.** У unMineable логин пишется как `XMR:адрес.воркер`, и то же деление
по `/` дало бы правдоподобный неправильный адрес — а неправильный адрес на балансовом API отвечает
не ошибкой, а чужим нулём. Про такую ноду консоль честно скажет, что прочитать не может;
электричество ей при этом считается по-прежнему.

**В таблицы выше это не подмешано.** Они построены на Hashvault, который знает только Monero.
Складывать две монеты в одну колонку «доход» — значит потерять то, чем они отличаются, поэтому
карта считается рядом, а не внутри.

## Что нужно знать про цифры

**Потребление.** Мощность берётся с датчиков CPU и GPU плюс 35 Вт на плату, память, диски и
потери БП.

Температура и мощность CPU читаются из MSR, для чего нужен доступ уровня ядра.
LibreHardwareMonitor 0.9.6 получает его через драйвер **PawnIO**, который ставится отдельно;
устаревший `WinRing0` эта версия уже не использует вовсе. Без PawnIO библиотека спокойно
стартует и отдаёт только то, для чего ядро не нужно — отсюда картина «GPU есть, CPU пусто»
(GPU читается через пользовательский API NVIDIA).

**Поставьте PawnIO на каждой ноде:** [pawnio.eu](https://pawnio.eu) →
[PawnIO_setup.exe](https://github.com/namazso/PawnIO.Setup/releases/latest/download/PawnIO_setup.exe).

Проверено на машине разработки: PawnIO отсутствует (нет ключа
`HKLM\SOFTWARE\Microsoft\Windows\CurrentVersion\Uninstall\PawnIO`, который читает сама LHM),
при этом в журнале `CodeIntegrity/Operational` нет ни одной блокировки — то есть ничего не
запрещено, просто нечем читать.

Совместимость PawnIO с включённой «Целостностью памяти» (HVCI) авторами прямо нигде не заявлена
— проверяйте на своей машине. Если после установки датчики не появились, смотрите
`CodeIntegrity/Operational`: блокировка драйвера пишется туда событием 3033.

Пока датчиков нет, агент не выдаёт ноль за измерение: помечает значение как оценочное (`~` в
таблице), берёт `powerFallbackWatts` и называет причину в **Nodes → Test connection** и
**Hardware & sensors**. Если решите остаться без датчиков — замерьте розеточным ваттметром один
раз под нагрузкой и впишите в настройки ноды.

**Доход.** Считается как ожидание от сложности сети: ваша доля хэшрейта × награда за блок ×
720 блоков в сутки. Это матожидание, а не выплата. Фактические начисления смотрите в
**Pool & wallet** — там же порог выплаты и сколько до него осталось.

**Хэшрейт.** Агент читает его из собственного HTTP API xmrig, который поднимает сам со случайным
токеном. Майнер, запущенный мимо агента, будет виден как процесс (`mining (no api)`), но без
хэшрейта, пока его не перезапустить через консоль.

## Безопасность

- Токен обязателен. Без него агент пускает любого, кто дотянется до порта, и пишет об этом в лог.
- Порт открыт только для `100.64.0.0/10`; ограничьте доступ ещё и ACL самого tailnet.
- `Stop` останавливает **все** процессы `xmrig` на ноде, а не только запущенные агентом: считается,
  что майнингом на этой машине распоряжается флот.
- Установка тянет релиз с GitHub на самой ноде, значит ноде нужен исходящий интернет.
  Установка в каталог, отличный от текущего, майнинг не прерывает.

## Сборка

```
dotnet build            # решение целиком
dotnet test             # тесты консоли (разметка, деньги, обновление)
dotnet run --project src/XmrigFleet.Agent      # агент в консоли, для отладки
dotnet run --project src/XmrigFleet.Console    # TUI
```

Целевой фреймворк — .NET 8. Датчики железа — LibreHardwareMonitorLib; агенту нужны права
администратора, иначе часть датчиков будет пустой (консоль это показывает в Nodes → Test
connection).
